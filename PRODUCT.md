# Product

## Platform

web

## Users

**Primary — practising engineers.** People working on reliability, data visualisation, or small self-contained tools. They arrive from a search result, a shared link, or a GitHub repository, usually mid-task, and decide quickly whether the writing or the tool is worth their time.

**Secondary — hiring managers, recruiters, and collaborators.** Evaluating Jian for a role, contract, teaching, or joint work. They read the About page and the project list as evidence rather than as prose.

A public archive read only by its author was explicitly ruled out: engineer readers come first, with the About page carrying the hiring signal alongside.

## Product Purpose

Publish writing and showcase open-source tools so that engineers find them useful and the people who might work with Jian can evaluate him.

Success is measured by three outcomes, all confirmed:

1. **Enquiries arrive** — roles, contracts, teaching, or collaboration.
2. **Peer credibility** — tools that get used, starred, and cited.
3. **Found and shared** — posts surface through search and other people sharing them, rather than the author pushing each one.

## Positioning

The differentiator is the work itself: small, complete tools with a stated point of view — a static API with no database "on purpose", a test-automation tool that is "KISS, no loops, no secret store" — plus writing that shows the reasoning behind building them. This is a builder's record, not a content-marketing surface: projects carry real star counts and posts describe real trade-offs.

## Operating Context

- Static site generated by **Eleventy 3** (Nunjucks templates, Markdown posts), deployed to GitHub Pages by a GitHub Actions workflow on every push to `main`.
- Dev loop: `npm start` (`eleventy --serve`, port 8000). `npm run build` writes to `_site/`.
- Routes: `/` home, `/writing/` all posts, `/about/`, `/posts/<slug>/`, plus `/404.html`, `/feed.xml`, `/sitemap.xml`, `/robots.txt`.
- Posts live in `src/posts/*.md` with frontmatter (`title`, `description`, `date`, `category`, `readingTime`); a directory data file applies the layout, the `post` tag, and the permalink.
- Post comments are **giscus**, backed by GitHub Discussions on the repository itself — there is no third-party comment host.

## Capabilities and Constraints

Confirmed:

- Home page: hero, a one-paragraph introduction, the three latest posts, two selected projects, and links to GitHub, LinkedIn, and email.
- Writing index listing every post; per-post pages with a reading-progress bar and a comment thread.
- About page: role, employer (ANZ), teaching history (Monash University), a list of specifics (29 original repositories since 2011, Robogo, working values), and contact links.
- Six projects showcased with star counts and language/type metadata.
- Light/dark toggle persisted in `localStorage`, defaulting to `prefers-color-scheme`.
- Accessibility already in place: skip link, visible focus rings, `prefers-reduced-motion` handling, `aria-label`s, semantic document structure.

Undecided, and not to be invented:

- No analytics or tracking exists, and none was requested. Do not add one without asking.
- Publishing cadence is unset; the archive holds two posts.

Hard constraint (confirmed as something future work must preserve):

- **Static hosting only** — no server, no database, no runtime cost. Anything requiring a backend, a database, or a build-time secret is out of scope until the user says otherwise.

## Brand Commitments

- The author is presented as **Jian** — the short form, deliberately, in the banner, page titles, structured data, and copyright.
- Voice is first-person, plain, and technical, comfortable admitting what did not work ("this codebase is small compared with real projects"). It is not marketing register.
- Real, verifiable numbers carry the proof (repository age, star counts). Nothing here is a fabricated claim.

## Evidence on Hand

- Two published posts, both categorised `Tools`.
- Six real open-source projects with genuine metadata: Malaysia API (37★, 26 forks), AITA store (12★), Sentiment analysis (7★), D3 Word Cloud Generator (5★, 8 forks), Robogo, Call Log to Calendar (2★).
- Author facts on the About page: Site Reliability Engineer at ANZ, previously taught software engineering at Monash University, 29 original repositories on GitHub since 2011.

Absences future work must not fabricate: there are **no** testimonials, customer logos, case studies, press mentions, benchmarks, download counts, or traffic figures.

## Product Principles

1. **Engineers first.** Judge every surface by whether a working engineer gets value fast; the hiring signal rides along rather than driving the design.
2. **The work is the proof.** Real repositories, real star counts, real trade-offs. Prefer evidence to adjectives.
3. **Static and self-contained.** No server, no database, no runtime cost. Complexity must earn its place.
4. **Reading is the product.** Posts are meant to be read to the end, so structure and typography serve comprehension over decoration.
5. **Findable.** Pages must stay indexable, well-titled, and well-described, because search and shares are a primary acquisition path.
